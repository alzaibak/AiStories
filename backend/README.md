# API Islamic Stories

API REST Node.js / Express, Sequelize et MySQL. Les routes sont montées sous `/api/v1`.

## Configuration et commandes

Copier `.env.example` en `.env`, configurer la connexion MySQL et définir `JWT_SECRET_KEY` et `OTP_HASH_SECRET` sur deux secrets aléatoires distincts (au moins 64 caractères chacun). Toute clé exposée doit être remplacée. Configurer le relais SMTP (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`) ainsi que deux origines HTTP(S) distinctes : `CLIENT_URL` pour le site public et `ADMIN_URL` pour le portail d’administration. Les codes expirent après 10 minutes, autorisent cinq tentatives et appliquent un délai de renvoi de 60 secondes.

```powershell
npm ci
npm run migrate
npm run dev
npm test
```

Le serveur applique les migrations versionnées avant d’écouter. Pour créer le super-administrateur initial, définir `SUPERADMIN_EMAIL` et `SUPERADMIN_INITIAL_PASSWORD` (14 caractères minimum, majuscule, minuscule, chiffre et symbole) dans `.env`, puis lancer `npm run seed:superadmin`. Le script hache le mot de passe, impose son changement à la première connexion et retire la valeur initiale du fichier. La récupération se fait uniquement depuis une console du serveur de production via `SUPERADMIN_RECOVERY_PASSWORD` et `npm run reset:superadmin`. Les anciens scripts `seed:admin` restent disponibles pour les installations historiques. Sauvegardez et vérifiez la base cible avant d’appliquer des migrations.

## Routes actives

- `/api/v1/reader/auth/register/*` : inscription lecteur avec vérification par code e-mail.
- `/api/v1/auth/login`, `/api/v1/auth/me`, `/api/v1/auth/email/*` : connexion lecteur, session et vérification d’adresse.
- `/api/v1/admin/auth/*` : connexion administrateur avec code e-mail, invitations réservées au `SUPER_ADMIN` et approbation des nouveaux administrateurs.
- `/api/v1/plans` : formules actives pour les lecteurs.
- `/api/v1/payments/books/checkout` et `/payments/subscriptions/checkout` : sessions Stripe Checkout réservées aux lecteurs.
- `/api/v1/payments/webhook` : événements Stripe vérifiés par signature et traités de façon idempotente.
- `/api/v1/subscriptions/:id/cancel` et `/resume` : gestion du renouvellement par son propriétaire.
- `/api/v1/admin/plans` et `/api/v1/admin/subscriptions` : gestion des formules et des états manuels; les états Stripe sont synchronisés par webhook.
- `/api/v1/admin/store-orders` : consultation des commandes papier payées et mise à jour de la préparation, de l’expédition et du suivi.
- `/api/v1/health` : disponibilité de l’API.
- `/api/v1/docs` : documentation interactive Swagger UI ; le document OpenAPI est disponible sur `/api/v1/openapi.json`.

## Données et sécurité

La migration `009-create-story-platform` ajoute le socle Sequelize du projet d’histoires : collections, histoires et parties, validation des quiz, médias et conformité de représentation, livres papier/numériques, panier et commandes, plans, abonnements, droits d’accès et idempotence des événements Stripe. Les migrations `010-add-quiz-attempt-timer` et `011-add-payment-workflow` ajoutent respectivement les tentatives minutées et les champs de paiement, d’adresse de livraison et d’identifiants Stripe. Le seed complet ajoute trois histoires arabes de démonstration en brouillon, deux livres de préparation non publiés et l’ebook original `kindness-lantern-demo`, publié à 4,90 EUR avec un fichier PDF local de démonstration. Son accès au téléchargement reste soumis à un droit d’achat valide, mais le fichier intégré évite de dépendre d’un bucket pour tester ce parcours.

Le seed des histoires crée également des quiz en brouillon avec leurs options liées, afin de tester l’éditeur sans publier de contenu de démonstration.

Les livres publiés et les formules actives passent par Stripe Checkout; une commande papier réserve le stock jusqu’au paiement ou à l’expiration de la session, puis le webhook attribue les droits numériques ou libère le stock. Les remboursements complets signalés par Stripe révoquent les droits numériques de la ligne concernée. Les états d’abonnement Stripe sont mis à jour depuis les événements signés du fournisseur. Configurez `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `CLIENT_APP_URL`, `BOOK_SHIPPING_FEE` et `SUBSCRIPTION_GRACE_PERIOD_DAYS` avant d’activer les paiements. Le tarif d’expédition doit être explicitement défini, même s’il est égal à zéro. Créez les formules avec un nom et les avantages saisis manuellement en arabe, anglais et français; la route `/api/v1/plans` masque une formule tant que sa traduction dans la langue demandée est absente. La migration `015-add-plan-translations` préserve les anciens noms et avantages arabes. L’application ne calcule pas les taxes; configurez vos prix et obligations fiscales avant d’accepter les paiements.

Les routes `/api/v1/reader/auth/*` fournissent l’inscription lecteur vérifiée par e-mail. `/api/v1/auth/password/request-code`, `/verify-code` et `/reset` permettent la réinitialisation lecteur; les rôles `ADMIN` et `SUPER_ADMIN` ne peuvent pas changer ou réinitialiser leur mot de passe depuis le site public. `/api/v1/collections`, `/stories`, `/books`, les routes `/quizzes` et `/reading-progress` exposent la lecture et les quiz; `lang=ar|en|fr` sélectionne le contenu manuel. `/api/v1/admin/content/*` gère les collections, histoires, revue, parties, vidéos, quiz, livres et médias. Le portail admin utilise `/api/admin/*` (alias réservé à l’origine admin) et des JWT avec audience admin. Les sessions lecteurs durent trois jours, celles des rôles d’administration trois heures.

La migration `012-add-book-translations` ajoute les champs de textes manuels des livres et peut être relancée si cette colonne existe déjà. La migration `013-align-email-challenge-roles` synchronise les rôles autorisés dans les défis e-mail avec les rôles des comptes. La migration `014-convert-legacy-buyers-to-readers` convertit les anciens comptes `BUYER` en comptes `READER` sans modifier leurs identifiants, afin qu’ils puissent utiliser la connexion et la réinitialisation lecteur. Les migrations initiales `001` à `008` sont conservées pour assurer la compatibilité des bases déjà créées et permettre aux migrations suivantes de s’exécuter dans le bon ordre. Les routes et l’interface de l’ancien système de tendering ont été retirées. Ne supprimez pas les migrations historiques d’une base déjà déployée.

Les images de contenu et les livres numériques utilisent `STORAGE_DRIVER=local` en développement par défaut. Les fichiers sont stockés sous `backend/private_uploads`, hors des dossiers statiques, et ne sont disponibles qu’au travers de routes de l’API qui appliquent les contrôles d’accès. `STORAGE_MAX_UPLOAD_BYTES` règle la taille maximale (20 MiB par défaut); le serveur génère les noms et vérifie le type réel du fichier par sa signature, y compris pour les PDF.

En production, définissez `STORAGE_DRIVER=s3` et `S3_BUCKET`. `S3_REGION` est facultatif (par défaut `us-east-1`). `S3_ENDPOINT` est facultatif pour AWS et nécessaire pour R2 ou MinIO. `S3_ACCESS_KEY_ID` et `S3_SECRET_ACCESS_KEY` sont facultatives ensemble si un rôle IAM ou équivalent est disponible. `S3_FORCE_PATH_STYLE` est facultatif et activé automatiquement pour les endpoints personnalisés. Le bucket doit rester privé et autoriser les formulaires POST depuis les origines de `CLIENT_DOMAIN`. Les formulaires présignés et URL de lecture expirent après cinq minutes. Toutes les variables sont décrites dans `.env.example`.

Helmet protège les en-têtes HTTP. CORS autorise `CLIENT_URL` pour l’API publique et `ADMIN_URL` pour les routes admin; le point de session `/auth/me` accepte les deux origines. Les requêtes d’authentification et de quiz sont limitées en débit. Les corps d’inscription, de connexion, de réinitialisation et de gestion de contenu sont validés avec Zod. La migration historique `004-remove-legacy-user-fields` convertit les anciens mots de passe AES en hash PBKDF2 avant de supprimer les colonnes historiques ; sur une base existante contenant de tels comptes, configurez `SECRET_PASSWORD` avant son exécution.

Les sessions sont émises avec un JWT unique à chaque connexion (`jti` distinct) : trois jours pour les lecteurs et trois heures pour les comptes d’administration. Les codes lecteur à six chiffres et admin à huit chiffres sont stockés sous forme de HMAC, expirent après 10 minutes, sont limités respectivement à cinq et trois tentatives et ne peuvent pas être réutilisés; un renvoi est possible après 60 secondes. La migration `016-publishing-auth-and-slugs` ajoute le workflow de publication, les métadonnées d’authentification et les redirections de slugs. La migration `017-repair-book-publication-date` répare le champ `books.publishedAt` s’il manque, même si la migration 016 est déjà enregistrée comme exécutée. La migration `018-expand-quiz-workflow` ajoute le workflow de quiz, les options traduites et l’historique de réussite, puis convertit les anciens choix en options. Les quiz sont modifiables depuis l’administration, doivent être soumis à la révision, et sont notés côté serveur; les réponses correctes ne sont jamais incluses dans les questions publiques. Aucun nouvel environnement n’est requis pour les quiz. La migration `003-remove-commerce-schema` fait partie de l’historique et peut supprimer des données commerciales obsolètes; vérifiez soigneusement la base avant toute migration.

Les migrations `019-community-phase-2`, `020-expand-media-video-policy` et `021-community-system` ajoutent les données communautaires, les métadonnées vidéo, les événements, équipes, dons, rappels et pages de politique. La migration `022-promotions-and-event-announcements` ajoute les codes promotionnels/cadeaux, les annonces des gagnants et les modèles d’e-mail; `023-recurring-donations` ajoute les dons mensuels et leurs factures idempotentes; `024-email-notification-queue` ajoute les préférences de livraison et la déduplication des courriels mis en file. Sauvegardez MySQL avant `npm run migrate`; ces dernières migrations n’ont pas été exécutées sur une base réelle dans cet environnement. Les dons récurrents utilisent Stripe Billing et peuvent être annulés depuis le compte lecteur; les reçus et confirmations utilisent les modèles e-mail actifs et nécessitent SMTP. Les codes promotionnels se créent dans l’administration et sont appliqués par le serveur au checkout. Les publications et résultats de quiz sont mis en file et envoyés via les modèles localisés; les lecteurs peuvent se désabonner des messages marketing depuis leur compte. Les rappels dus sont traités automatiquement par le processus API selon `REMINDER_POLL_INTERVAL_MS` (minimum 5 secondes, défaut 60 secondes), et peuvent aussi être lancés via `/api/v1/admin/system/reminders/process`. Les médias privés vidéo acceptent MP4/WebM selon `STORAGE_MAX_UPLOAD_BYTES`; utilisez le stockage local uniquement pour le développement et un bucket privé S3-compatible en production.
